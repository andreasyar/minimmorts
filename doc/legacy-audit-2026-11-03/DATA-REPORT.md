> Состояние на момент аудита, до переноса выбранных материалов. Итоговое размещение описано в [doc/README.md](../README.md).

Проверен весь `/home/andrey/src/minimmorts-legacy`: **28 694 файла,
494 597 622 байта (471,7 МиБ)**. Размеры ниже — логические размеры файлов,
а не занятое место с учётом особенностей файловой системы.

Самые полезные материалы для переноса — игровой комплект спрайтов,
два разных снимка работающей игры и точные версии трёх библиотек сервера.
Логи полезны как исторические образцы поведения, но их лучше хранить отдельно
от повседневного кода. Бекапов игровой БД, схемы БД и дополнительных авторских
документов в проверенном каталоге не обнаружено.

Это инвентаризация и предложения по размещению. Ресурсы и архивы пока не
переносились, Git index не менялся; добавлены только отчёт, скрипт и JSON аудита.

## Серверные логи

Найдены 62 файла логов, около 10,4 МиБ с повторениями.
После сравнения содержимого: **18 непустых уникальных логов,
5 098 845 байт**, и одно общее пустое содержимое.
Непустые логи отсутствуют в Git; пустое содержимое, естественно, в нём есть.

Непустые экземпляры находятся в сохранённых
`server/NetBeans-7.1.2 project/` и называются
`minimmorts.GlobalLogFile-<timestamp>.txt`.
Имена разных файлов не гарантируют разные данные: дедупликация выполнена по SHA-256.

Внутри — реальные записи запусков 15, 25 и 27 июня 2012 года:

- Создание и удаление клиентов и юнитов.
- Ожидание отчётов и переинициализация клиентов.
- Создание и изменение путей движения с координатами и номерами ходов.
- Диагностика обработки сообщений и серверного цикла.

Их можно использовать для изучения старого поведения и подбора примеров
для будущих проверок. Они не являются сохранением мира или воспроизводимым
replay: по наличию логов нельзя обещать восстановление состояния сервера.
Пустые файлы отдельных логгеров и повторные экземпляры переносить не нужно.

```sh

```

Скрипт использует стандартную библиотеку Python и Git, читает legacy
и записывает только JSON рядом с собой. Классификация привязана к найденной
структуре этого архива. Вывод об отсутствии данных относится только к этому
каталогу, а не к другим внешним резервным копиям.
